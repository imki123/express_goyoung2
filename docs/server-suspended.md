# 서버 중단 조사 기록

## 확인된 사실

- Render에서 `Service-Initiated` 트래픽 5.41GB가 관찰된 뒤 서비스가 일시 중단되었습니다.
- 이전 전역 오류 처리기는 Express 오류 미들웨어의 4개 인자 형식이 아니었고, 오류 시 `IncomingMessage` 전체 객체가 대량으로 로그에 기록되었습니다.
- 현재 로컬 변경에는 `GET /ping`의 204 응답과, 오류 메시지만 기록하는 4개 인자 전역 오류 처리기가 포함됩니다.
- 10분 단위 응답 본문 추정치는 응답의 `Content-Length`를 내부적으로 합산한 값입니다. Render 청구량, MongoDB 와이어 바이트, Axios 아웃바운드 바이트, TLS 또는 프록시 오버헤드, 청크 전송 응답 바이트는 포함하거나 대체하지 않습니다.
- 10분 요약은 현재 10분 창의 알려진 `Content-Length` 바이트, 프로세스 시작 이후 누적 알려진 바이트, 실제 경과 시간을 기준으로 환산한 시간당 평균을 기록합니다.
- 현재 10분 창의 알려진 `Content-Length` 바이트가 5 MiB를 초과하면 추정치 경고를 한 번 기록하고 `preventSleep`의 반복 호출만 중지합니다. 서버, MongoDB 연결, 응답 집계 타이머 및 이미 시작된 요청은 계속 실행됩니다.

## 원인 판단

| 항목                        | 근거 신뢰도 | 판단                                                                                                                                |
| --------------------------- | ----------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `IncomingMessage` 대량 로그 | 높음        | 로그 폭증 문제는 확인되었지만, 이것만으로 `Service-Initiated` 트래픽의 원인이라고 증명할 수는 없습니다.                             |
| 자체 서버 호출              | 중간        | `preventSleep`이 환경변수로 설정된 서버에 10분마다 Axios로 `/ping`을 호출합니다. 대상 설정에 따라 아웃바운드 후보가 될 수 있습니다. |
| 그 밖의 외부 호출           | 낮음        | 현재 조사만으로는 확정하지 못했습니다. 배포 환경의 요청 및 네트워크 사용량과 함께 확인이 필요합니다.                                |

Render의 트래픽 분류와 청구 기준은 [Billing](https://render.com/docs/billing), 로그 확인 방법은 [Logs](https://render.com/docs/logging) 문서를 기준으로 확인합니다.

## 배포 전 확인

1. 로컬 변경을 배포합니다.
2. Render 로그에서 오류 로그가 메시지 중심으로 남는지 확인합니다.
3. `/ping`이 204를 반환하는지 확인합니다.
4. 10분 단위 내부 추정치와 Render 대시보드의 트래픽을 같은 기간으로 비교하되, 두 값이 같은 측정값이라고 해석하지 않습니다.

현재 변경은 로컬 상태이며, 배포 완료 여부는 아직 확인하지 않았습니다.
